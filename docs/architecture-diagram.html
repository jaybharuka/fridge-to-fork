Fridge to Fork Architecture

Fridge photo → AI vision → recipe planning → Swiggy MCP ordering (Instamart groceries or Swiggy Food delivery)

Security & Auth

  • • Swiggy OAuth2 + Dynamic Client Registration
  • • Access token kept in a signed server-side session cookie (itsdangerous) — never sent to the browser as JS-readable state
  • • No API keys or client secrets in frontend code
  • • Every MCP call is scoped to the logged-in user's own Swiggy token

AI & External Services

  • • Google Gemini — fridge vision + recipe/text generation, with a model fallback chain
  • • AWS Rekognition (boto3) — vision fallback only, used if Gemini is unavailable
  • • Unsplash, YouTube Data API, TheMealDB — best-effort recipe enrichment, never blocking

Deployment

  • • Backend: FastAPI on Render (free tier)
  • • Frontend: static single-page app on Vercel
  • • GitHub Actions cron pings /health every 10 min to prevent cold starts
  • • No persistent database — state is per-session only (no inventory/order history stored)
